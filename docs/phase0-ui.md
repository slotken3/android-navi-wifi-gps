# フェーズ0: ナビホーム(UIの試作)

要件定義書「車載ナビ改造 要件定義書(Joying UIS7862)」の UI 要件(U1〜U12)と、
接続状態の表示(N5〜N7)を、実際に操作できる画面として作ったもの。
コア部分(通信量の実測・切断の記録の保存・走行判定)はデモ値で動かしている。

## 構成

既存の WifiWatchdog アプリの中に、ホーム画面「ナビホーム」を追加した。
アプリを分けない理由は、止めないアプリの一覧に名前を合わせる作業(O2)と
システムアプリ化(U9)が1つで済むため。

- インストールすると、アプリ一覧に「ナビホーム」と「Wi-Fi自動復旧」の2つが出る。
- 既定のホームにはならない。設定 → ホームアプリ で有効にしたときだけホームの候補になる。
  (有効のままインストールすると、ホームボタンで選択画面が出て、走行中に操作を求めるため)
- コードは `app/src/main/java/com/livraison/wifiwatchdog/home/`。既存の監視処理には手を加えていない。

## 画面

| 画面 | クラス | 内容 |
|---|---|---|
| ホーム | `HomeActivity` | 大きなタイル(ナビ・動画・音楽・会議・CarPlay・ドラレコ・接続状態)、下段にラジオ・電話・アプリ一覧・設定。上段に時計とWi-Fi監視の稼働表示 |
| 選択パネル | `HomeActivity` 内 | 動画・音楽・会議のタイルを押すと出る。2タップ目でアプリが開く。入っているのが1つだけなら選ばずに開く |
| 接続状態 | `ConnectionActivity` | 今の経路(Wi-Fi / SIM)と通信できるか、SIMの通信量、Wi-Fi監視の状態、切断の記録(停車中・走行中で絞り込み) |
| 設定 | `SettingsActivity` | 下の7分類 |
| アプリ一覧 | `AppListActivity` | 入っているアプリを開く。タイルへの割り当てにも使う |

設定の分類:

| 分類 | 内容 |
|---|---|
| ホーム画面のアプリ | タイルに割り当てるアプリの変更。動画・音楽・会議は追加と削除(U11) |
| 通信 | SIMの月の上限、Wi-Fi監視の設定への入口 |
| 会議の機材 | USB機器・カメラ・マイクの一覧(U12の確認用) |
| ホームアプリ | 既定のホームにする / 純正に戻す。全画面とホームボタン(U10)は段階1 |
| 調査(段階0) | 画面の実寸、protected_app.txt の読み取り(O1)、衛星情報 |
| 表示確認 | 接続経路・走行中・通信量をデモ値に切り替える |
| このアプリ | バージョン、パッケージ名 |

## 動くもの・デモ値のもの

| 実際に動く | デモ値(段階1で実装) |
|---|---|
| タイルからのアプリ起動、アプリ一覧 | SIMの通信量(N5) |
| 接続経路と通信できるか(Androidの判定を読むだけ) | 切断の記録(N6) |
| Wi-Fi監視サービスの稼働表示 | 走行中の判定(U5。段階1でGPSの速度から) |
| USB機器・カメラ・マイクの一覧 | 全画面で開く・隅のホームボタン(U10) |
| protected_app.txt の読み取り(読むだけ) | |
| 既定のホームの切替と、純正への戻し | |

デモ値にしている画面には「デモ値」「サンプル」の印を付けている。
表示確認で状態を変えているときは、ホーム画面に「デモ表示中」と出る。

## 要件との対応

| ID | 対応 |
|---|---|
| U1 | ホームのタイル。動画・会議などは2タップで開く |
| U2 | 押せるものはすべて1辺64dp以上 |
| U3 | 暗い配色のみ。文字も純白にしない。既存の設定画面・衛星情報画面も暗い配色にした |
| U4 | 下段にラジオ・電話。純正アプリの名前(`com.syu.radio` 等)は推測なので、実機で選び直せる |
| U5 | 走行中は設定とタイルの長押しを受け付けない。会議は音声のみの表示 |
| U6 | ホームの候補は設定から有効にする。パッケージ名の変更(O2)と、ホーム表示時の監視再開は段階1 |
| U10 | 段階1(設定に項目だけ置いた) |
| U11 | 会議(ほか動画・音楽)に並べるアプリを設定で追加・削除 |
| U12 | 会議の機材の画面でUSB機器・カメラ・マイクを確認。走行中は音声のみの表示 |
| N5 | 通信量の表示と月の上限(80%で黄、100%で赤)。値はデモ |
| N6・RT4 | 切断の記録の画面(停車中・走行中の絞り込み)。値はサンプル |
| N7 | ホームの接続状態タイルと、接続状態の画面 |
| O1 | 調査 → protected_app.txt を読み取る |

## 画面密度について

実機の画面密度は未確認。160dpi なら 1024×600dp、240dpi なら 683×400dp になる。
タイルの寸法は比率で決めているので、どちらでも崩れないようにしてある。
実機の値は 設定 → 調査 → 画面の実寸 で確かめられる。

## 画面の確認(CI)

`.github/workflows/build-apk.yml` の `ui-check` ジョブが、エミュレーター
(1024×600・160dpi・Android 10・日本語)で各画面を開いてスクリーンショットを撮る。
開いた直後にアプリが落ちたらジョブが失敗する。

- 撮影の手順: `scripts/ui-screenshots.sh`
- 結果: Actions の実行結果 → Artifacts の `ui-screenshots`
- エミュレーターには ABEMA などが入っていないので、タイルは「アプリが見つかりません」と出る。
- 表示状態は、デバッグ版だけが受け付ける intent の追加情報(`demo_route` など)で切り替えている。

## 実機で確かめること

- [ ] 「ナビホーム」が起動し、タイルの大きさと文字が見やすいか(昼・夜)
- [ ] 設定 → 調査 → 画面の実寸(dpi の値)
- [ ] 設定 → 調査 → protected_app.txt を読み取れるか。件数、`com.tiantian.ttclock` の有無
- [ ] ナビ・動画・会議の各アプリが、タイルから開けるか
- [ ] CarPlay・ドラレコ・ラジオ・電話のアプリ名(入っていなければ長押しで選ぶ)
- [ ] 設定 → ホームアプリ で既定のホームにできるか。純正に戻せるか
- [ ] USBのウェブカメラとマイクをつないで、会議の機材に出るか。ドラレコと同時につないだとき
- [ ] スリープ復帰後、ホーム上段の「Wi-Fi監視」が停止中になるか(O3の確認に使える)
