# 車内Wi-Fi 自動復旧アプリ (WifiWatchdog)

UIS7862搭載の中華製カーナビ(Android 10)で、車内Wi-Fiが切断された際に
自動で再接続を試みる常駐アプリです。

## 仕組み

1. `WifiMonitorService` がフォアグラウンドサービスとして常駐し、
   - `WifiManager` のブロードキャスト(切断・Wi-Fi OFF)を監視
   - 15秒ごとに「接続表示はあるが実際は通信できない」状態(疑似切断)も
     `generate_204` への疎通確認でチェック
2. 異常を検知すると次の順で復旧を試みます。
   1. `reconnect()` による再接続
   2. 対象SSIDの保存済み設定を `enableNetwork()` で明示的に有効化
   3. 設定自体が失われていればパスワードから再登録
   4. 3回連続で失敗したらWi-Fi自体をOFF→ONしてリセット
3. 端末起動時は `BootReceiver` がサービスを自動起動します。

## ビルド方法

1. Android Studioで本フォルダを開く(Gradle同期)。
2. `app/build.gradle` の `targetSdkVersion` は **28のまま変更しないでください**。
   Android 10でアプリからWi-Fiを直接ON/OFF・設定変更するための必須設定です
   (29以上にすると `setWifiEnabled` 等が事実上機能しなくなります)。
3. `Build > Generate Signed Bundle / APK` でAPKを作成。

## 導入方法(カーナビ本体への設定)

1. APKを本機にコピーし、ファイルマネージャー等からインストール。
   - 提供元不明のアプリのインストールを許可する必要があります。
2. アプリを起動し、
   - 対象SSID(空欄なら現在つながっているネットワークをそのまま維持する動作)
   - パスワード(端末に既に保存済みのネットワークなら空欄でOK)
   を入力して「設定を保存」。
3. 「監視を開始」をタップ。
4. 「バッテリー最適化の除外を設定」をタップし、本アプリが
   スリープ中や画面OFF時にkillされないようにする。
5. 端末のシステム設定内に「自動起動管理」「アプリ保護」「電源管理」等の
   独自メニューがある機種(UIS7862系でよくある)では、そこでも
   本アプリの自動起動・バックグラウンド動作を個別に許可してください。
   (この設定はメーカー・ROMごとに項目名・場所が異なります)

## 権限について

- 位置情報の許可がないと、Android 8以降では接続中のSSID名を
  正しく取得できません(初回起動時にダイアログが出ます)。
- `RECEIVE_BOOT_COMPLETED` は端末再起動時の自動起動に必要です。

## みちびき(QZSS)を本当に使っているか確認する

メイン画面の「衛星情報を見る」から、今チップが捕捉している衛星を
衛星系(GPS/みちびき/GLONASS/Galileo/BeiDou)別に一覧できます。

- **みちびきが「捕捉:0機」の場合** → そもそもGNSSチップ/アンテナが
  みちびきのL1信号を受信できていません。これはアプリ側の設定ではなく
  ハードウェア(GNSSチップの型番・アンテナ特性)と、チップに書き込まれた
  衛星系有効化設定(多くは `/vendor/etc` 以下の設定ファイルやチップの
  ファームウェアで決まる)に依存するため、アプリだけでは有効化できません。
- **捕捉はしているが「測位使用:0機」の場合** → 信号は受かっているが
  信号強度(CN0)不足などで測位計算からは除外されています。
  屋外・見晴らしの良い場所で再確認してください。
- **測位使用:1機以上** → みちびきは実際に測位に使われています。
  一般的なGPS単独より高精度・高安定な位置が得られている状態です。

みちびきが全く捕捉できない場合、次のような原因が考えられます。

1. GNSSチップ自体がQZSS非対応(古い/低価格なGPS単独チップ)
2. チップは対応しているが、AGPS/GNSS設定ファイルで無効化されている
   (rootが取れれば `/vendor/etc/gnss/...` 等の設定ファイルを調整できる
   場合がありますが、ファイル配置・書式はチップベンダー(例: UNISOC/
   AllyStar/ComNav等)ごとに異なり、汎用的な手順は提示できません)
3. アンテナ特性・取り付け位置の問題(車内設置だとガラス越しの減衰が
   大きく影響します)

## ファームウェア組み込みについて

- root権限がある場合、本アプリを `/system/priv-app/` に配置し
  `platform` 署名で署名し直すことで、Wi-Fi制御やGNSS設定へのアクセス権を
  より強く持たせることができます(いわゆる「システムアプリ化」)。
- ただし完全な firmware(system.img)の再構築・書き込みは、この種の
  ノーブランド車載機では公式のビルド環境やソースが公開されておらず、
  失敗時の文鎮化リスクが高いため、具体的な改造手順は端末の型番・ROMの
  出どころが特定できないと提示できません。まずは現状のroot取得可否・
  カスタムリカバリの有無を確認することをお勧めします。

## 既知の制約

- 一部のOEM ROMでは `BOOT_COMPLETED` の発火が遅い/発火しないことがあるため、
  Wi-Fi状態変化イベントもトリガーに追加していますが、それでも自動起動しない
  場合は前述の「自動起動管理」設定を確認してください。
- ルート化されている場合は `wpa_cli reconnect` をシェル経由で叩く方式に
  切り替えるとさらに確実性が上がります。必要であれば拡張可能です。
